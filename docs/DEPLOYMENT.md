# Permanent local deployment (Windows)

This is the layout used on the integration machine since 2026-10-13. Every path below is
machine-specific and lives **outside** the repository. Only this description is committed.

| Purpose | Location | Notes |
|---|---|---|
| Source repository | wherever you cloned it | may sit in OneDrive; nothing runtime-related is written there |
| Python environment | `%LOCALAPPDATA%\RevEngNexus\venv` | `uv venv … --python 3.12` + `uv pip install -e "<repo>[dev]"` (editable: repo edits take effect on restart) |
| Configuration | `%LOCALAPPDATA%\RevEngNexus\config\providers.yaml` | generated by `reveng-nexus config init`; never committed |
| Workspace (authorised samples only) | `%USERPROFILE%\RevEngNexus\workspace` | the only folder Nexus will read targets from |
| Data: evidence DB, audit log, staged copies, engine projects, provider logs, reports | `%LOCALAPPDATA%\RevEngNexus\data` | not synced; SQLite WAL files must not live in OneDrive |
| Backups made during migrations | `%LOCALAPPDATA%\RevEngNexus\backups` | old configs, fixture hashes |
| Ghidra | `%LOCALAPPDATA%\Programs\Ghidra\ghidra_12.1.4_PUBLIC` | official release zip; SHA-256 checked against GitHub's published digest |
| uvx package caches (re-mcp-ghidra, mcpyghidra) | `%LOCALAPPDATA%\uv\cache` | managed by uv |
| Claude Code registration | `%USERPROFILE%\.claude.json` (user scope) | written by `claude mcp add --scope user` |

## Set up from scratch

```powershell
$repo = "<path to your reveng-nexus checkout>"
$base = "$env:LOCALAPPDATA\RevEngNexus"
uv venv "$base\venv" --python 3.12
$env:VIRTUAL_ENV = "$base\venv"; uv pip install -e "$repo[dev]"
$nx = "$base\venv\Scripts\reveng-nexus.exe"

Set-Location $repo   # config init finds config\providers.example.yaml here (or pass --example)
& $nx config init `
    --workspace "$env:USERPROFILE\RevEngNexus\workspace" `
    --data-dir "$base\data" --create-dirs `
    --enable ghidra_remcp --enable ghidra_mcpy `
    --ghidra-dir "$env:LOCALAPPDATA\Programs\Ghidra\ghidra_12.1.4_PUBLIC" `
    --output "$base\config\providers.yaml"

& $nx --config "$base\config\providers.yaml" --check-config      # exit 1 on errors, prints fixes
& $nx --config "$base\config\providers.yaml" providers check      # starts each provider on its own

claude mcp add --scope user reveng-nexus -- "$base\venv\Scripts\reveng-nexus.exe" `
    --config "$base\config\providers.yaml" serve
claude mcp get reveng-nexus                                       # should report: Connected
```

`--check-config` is static: it starts nothing and creates nothing. It reports missing
workspace roots and unwritable data directories as errors. Missing provider executables,
unset `${VARS}`, install-dir variables (`GHIDRA_INSTALL_DIR`, `IDADIR`, `JADX_MCP_HOME`)
pointing nowhere, and data directories inside OneDrive or Dropbox are reported as warnings.

## Changing paths later

- **Different workspace or data folder.** Rerun `config init` with new
  `--workspace` / `--data-dir` and `--force`, or edit `providers.yaml`. A different
  `data_dir` starts with an empty evidence DB unless you copy the old one (below).
- **Moving the evidence DB.** Stop Claude Code sessions using the gateway first, then copy
  with SQLite's backup API, never as a live file copy:
  `python -c "import sqlite3; s=sqlite3.connect(r'OLD\evidence.sqlite3'); d=sqlite3.connect(r'NEW\evidence.sqlite3'); s.backup(d)"`.
  Targets keep their recorded absolute path. After moving samples, run
  `nexus_inspect_target` on the new path (same SHA-256), which updates it.
- **New Ghidra version.** Extract it, then rerun `config init --ghidra-dir … --force` (or
  edit `GHIDRA_INSTALL_DIR` in both Ghidra providers) and `providers check`.
- **Moving the venv.** Recreate it, then `claude mcp remove reveng-nexus -s user` and
  `claude mcp add …` with the new executable path.

## Migration performed on 2026-10-13

The first verification used temporary paths under `C:\tmp`. They were replaced as follows:

1. Ghidra moved (not re-downloaded) from `C:\tmp\rnx-tools` to `%LOCALAPPDATA%\Programs\Ghidra`.
2. The evidence DB was copied with `sqlite3.Connection.backup` to the new data dir.
   `PRAGMA integrity_check` returned `ok`, and all data is preserved: 4 cases, 1 target,
   47 evidence records, 3 comparisons. The audit log and reports were copied too.
3. The old config was moved to `backups\providers.yaml.tmp-paths-2026-10-13`. The original
   `C:\tmp\rnx-lab` data was left in place as a fallback and can be deleted.
4. The benign fixture was regenerated deterministically (`tests/fixtures/elf_builder.py`)
   into the workspace. Its SHA-256 `59bb6fa4…eef9f` matches the target already in the DB.

## Isolation

RevEng Nexus provides **no sandbox**. The read-only MCP policy stops tools from changing
analysis databases. It does not protect you from a malicious file that exploits a parser
in Ghidra, IDA, Binary Ninja, JADX, pyelftools or pefile. Analyse unknown or potentially
hostile samples only inside a properly isolated VM (snapshotted, no host credentials, no
outbound network by default), with Nexus and the engines installed **inside** that VM.
